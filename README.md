## 考核一 · C++ 三题

代码在 `exam1/` 里。

### 第 1 题 · 10 个数升序输出（exam1_1.cpp）

我先把 10 个数读进一个数组里，然后用冒泡排序输出。内层循环我一开始写的是 `j < N - 1`，后来改成 `j < N - i - 1`，因为每跑完一轮末尾就会多一个已经排好的数，不用再去比它了。N=10 的时候，比较次数从 81 次降到 45 次。

踩的坑：读入那行我把 `a[i]` 写成了 `std::cin >> a[N];`。N 是 10，合法下标只到 9，所以这是越界。编译器没有报错，程序也能跑，但排序结果不对。

我开始写的时候没有考虑到数组的位置，也没有考虑到代码的效率性。我一开始以为越界编译器会报错，因为在 Python 里出错是会直接报错的 —— C++ 的越界和 Python 的不一样，这是我在和 AI 讨论的时候发现的一个认知错误。后来 AI 做了一个示例给我看，同一个程序连跑四次，读出来的结果都不一样，我才知道 C++ 的越界不会报错，读到什么全看运气。

后来我又试了同一份代码，用 `-O0` 编译一句警告都没有，换成 `-O2` 就报出来了。我理解是因为 `-O0` 是一句一句翻译的，不把整段代码联系起来看，所以看不出越界；`-O2` 会先通读一遍，才能发现。所以不是编译器查不了，是 `-O0` 下它不做这个分析。

### 第 2 题 · 结构体与指针（exam1_2.cpp）

定义 `struct Student`，写 `input()` 和 `display()` 两个函数，通过指针接收结构体、用 `->` 取成员，在 `main()` 里用 `new` 动态创建一个。

一开始我完全分不清"指针"和"对象"。后来我想明白了，`s` 是对象，像一个盒子，`s.name` 就能直接拿到；`p` 是指针，更像一张写着地址的纸条，纸条上本来就没有 `name` 这个格子，得顺着纸条找到那个盒子，也就是写 `p->name`。其实 `p->name` 和 `(*p).name` 是一回事，就是对指针用 `.` 编译器会直接报错。

为什么要传指针这件事，我是想通了 C++ 传参数的方式之后才明白的。C++ 默认是把参数复制一份给函数的，函数里改的是复制出来的那一份，出来以后原来那个对象一点没变，所以得把地址传进去才行。我写了个演示程序，把两个地址打出来对比过。

`new` 是在堆上开一块内存，同时会调用构造函数；`delete` 会先调用析构函数，再把内存还给系统。这两个要配对写，少一个就是内存泄漏。

踩的坑：箭头位置写反过（`->pscore`）、函数名 `display` 拼成了 `displey`、输出的中文冒号漏掉过 —— 都是编译器报错或者对照题目才发现。

### 第 3 题 · Car 类（exam1_3.cpp）

定义 `class Car`，私有成员 `color` 和 `number`，公有的构造函数、析构函数、`display()`，在 `main()` 里创建两个对象。

第一次接触"类"，我理解就是把数据和操作数据的函数打包放在一起。构造函数的名字和类名一样，没有返回类型，创建对象的时候会自己调用，不能手动去调。析构函数是 `~` 加上类名，对象被销毁的时候会自己调用，想证明的话在里面打印一句话就能看到。

我的程序实际输出：

```
颜色：红色  车牌号：1001
颜色：蓝色  车牌号：1002
Car对象被销毁了，车牌号1002
Car对象被销毁了，车牌号1001
```

car2 是后创建的，却先被销毁。

这是因为栈是 LIFO，析构是反过来的。后面的对象可能会用到前面的对象，所以让后面的先销毁，这样它活着的时候前面那个才还在。它们是在离开作用域的时候被销毁的，不是程序结束的时候。new 出来的对象不一样，因为它在堆上，不写 delete 的话析构函数根本不会被调用 —— 我实测过，程序正常跑完了，但「Car对象被销毁了」一次都没打印。

`class` 和 `struct` 其实只有一个本质区别，就是默认的访问权限不一样，`class` 默认是 private，`struct` 默认是 public，其他方面都一样。把成员设成 private 是为了封装，不然在 main 里直接写 `car1.number = -999;` 也不会有人拦着。

踩的坑：`class Car()` 多写了一对括号；`};` 放错位置让 `display()` 跑到类外面去了；字符串用了单引号，`std::cout << '  ';` 打出来是数字 8224，必须用双引号。

## 考核二 · ROS 2

环境是 VirtualBox 里装的 Ubuntu 24.04 LTS，ROS 2 Jazzy，用鱼香 ROS 的一键安装脚本装的。

我先建了工作空间 `~/nav_ws`，把 `src.zip` 解压出来的 `daohang` 包放进 `src/`，然后 `colcon build --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=Release`，再 source 一下环境变量，最后 `ros2 run daohang daohang.cpp` 就跑起来了。

构建成功：

```
Starting >>> daohang
Finished <<< daohang [1.83s]

Summary: 1 package finished [2.08s]
```

截图在 `exam2/` 里，详细说明在 `exam2/说明.md`。

运行命令必须写成 `ros2 run daohang daohang.cpp`，因为 `CMakeLists.txt` 里那个目标名是带 `.cpp` 的，我第一次少写了就报找不到可执行文件。还有就是不 source 不行，系统不知道你刚构建了什么，会报 `Package 'daohang' not found`。

踩的坑：`colcon build` 报 `unrecognized arguments: --symlink-install`，这条命令教程里明明是对的，后来发现是中文输入法把 `-` 打成了全角 `－`；还有一次 `ros2 run` 报 `找不到命令 "ros"`，是 `2` 被打成了全角 `２`，屏幕上几乎看不出区别。另外有一次运行时终端输出一直正常，桌面上却弹出「应用程序 ros2 意外停止」，我判断崩的是 `ros2` 这个命令行外壳，不是我们构建的程序。

## 考核三 · GitHub

仓库地址：https://github.com/zhenghao200607/2027new

我理解 git 是分三步走的，`git add` 是先把改动的文件挑到暂存区，`git commit` 是把它记成一个提交存在本地，`git push` 才是推到 GitHub 上去。分三步的好处是可以自己挑要提交哪些文件，比如改了 5 个文件但只想提交其中 3 个。而且每个 commit 都像一个存档点，改坏了还能退回去。

踩的坑：第一次 push 报 `Password authentication is not supported for Git operations`，查了才知道 GitHub 现在禁止用账号密码做 git 操作，必须用 Personal Access Token。另外 push 经常报 `Connection was reset`，但因为 commit 已经存在本地仓库了，代码不会丢，重试就好。
